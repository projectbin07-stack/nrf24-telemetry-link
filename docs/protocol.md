# Protocol reference

Three layers, each with its own integrity check:

```
application message   version | type | body                     (messages.h)
link frame (radio)    5-byte header | fragment of message+CRC16  (link.h)
gateway serial packet COBS( version | kind | seq | len | body | CRC16 ) 0x00  (serial_frame.h)
```

All multi-byte integers are little-endian. Both CRCs are
**CRC-16/CCITT-FALSE**: polynomial 0x1021, initial value 0xFFFF, no
reflection, no final XOR; `crc("123456789") = 0x29B1`.

`test/vectors/link_vectors.json` holds byte-exact examples of every layer.
It is generated by `nrflink vectors --write` and checked by both the C++
(`test/test_vectors`) and Python (`host/tests`) suites.

## 1. Link frame (one ESB payload, at most 32 bytes)

| Byte | Bits | Field | Meaning |
|---|---|---|---|
| 0 | 7..5 | type | 0 = idle, 1 = reliable fragment, 2 = best-effort fragment, 3..7 rejected |
| 0 | 4 | ack_valid | byte 3 carries a valid acknowledgement |
| 0 | 3..0 | phase | sender's position in the current hop slot, in 1/16 of the dwell time |
| 1 | | seq | message sequence number, per channel, mod 256 |
| 2 | 7..4 | frag_index | 0..15 |
| 2 | 3..0 | frag_count - 1 | 0..15 (1..16 fragments) |
| 3 | | ack | last reliable `seq` the sender of this frame has delivered |
| 4 | | hop | hop index the sender is on |
| 5..31 | | fragment | bytes `[27 * frag_index, 27 * frag_index + 27)` of `message || crc16` |

Rules (enforced identically in C++ and Python):

* A frame shorter than 5 or longer than 32 bytes, with type 3..7, with
  `frag_index >= frag_count`, an idle frame with payload, or a data frame
  without payload is **malformed** and counted, nothing else happens.
* The CRC is computed over `seq || message` and appended low byte first, so a
  fragment from a different message with the same length cannot complete a
  reassembly by accident.
* Every fragment except the last carries exactly 27 bytes. The largest
  message is `LINKCORE_MAX_MESSAGE` bytes (160 by default, 64 on the
  ATmega328P builds); 16 fragments would allow up to 430.
* `fragment_count(n) = ceil((n + 2) / 27)`: 1..25 bytes fit one frame,
  26..52 two, and so on.

### Reliable channel (commands)

Stop-and-wait. `send_reliable()` is refused while a message is outstanding.

1. All fragments are sent in order. If the radio reports a fragment as not
   acknowledged (MAX_RT on the node), that fragment is sent again next.
2. After the last fragment the sender waits `reliable_timeout_ms` (100 ms)
   for a frame from the peer with `ack_valid` and `ack == seq`. Any frame
   type can carry the ack.
3. On timeout the whole message is sent again. Every fragment failure and
   every timeout uses one of `reliable_max_attempts` (8); after that the
   message is reported as failed.
4. The receiver delivers a message whose `seq` differs from the last
   delivered reliable `seq`, and acknowledges both new messages and
   duplicates. If it owes an ack and has nothing else to send, it sends an
   idle frame.

Limitations: one outstanding message; after a reboot a sender could reuse
the `seq` the peer delivered last, so the firmware starts from a random
`seq` (`set_next_sequences()`).

### Best-effort channel (telemetry)

* One message slot. `send_unreliable()` replaces a message that has not
  started to go out yet (counted as `unreliable_replaced`), and is refused
  while a message is part way through its fragments.
* If a fragment fails, the rest of that message is abandoned
  (`unreliable_aborted`), since the receiver could not complete it anyway.
* The receiver drops a fragment of the message it delivered last
  (`duplicates`) and counts sequence gaps of less than 128 as
  `unreliable_lost`.

### Channel hopping

* Sequence: candidates `first, first + spacing, ... <= last` are shuffled by a
  Fisher-Yates shuffle driven by xorshift32 (13, 17, 5) seeded with the
  network seed (0 is replaced by 0x9E3779B9); the first `count` are used.
  Defaults: seed 0x4E524634, channels 2..80 step 2, 8 channels.
* The node (master) changes channel every `dwell_ms` (50 ms) and does not
  start a transmission in the first or last 1/16 of a slot (guard time).
* The gateway (follower) sets its slot start from each received frame's hop
  index and phase (assuming the middle of the phase bucket). After
  `lost_slots` (4) consecutive slots without a valid frame it parks on one
  channel for `(count + 1) * dwell_ms`, which the master is guaranteed to
  visit, then moves to the next index if nothing was heard (so a jammed
  channel cannot keep it parked forever).

## 2. Application messages

`message = version:u8 (= 1) type:u8 body`

| Type | Name | Body | Bytes |
|---|---|---|---|
| 0x01 | battery | `bus_mv:u16 current_ua:i32 power_uw:i32 charge_uah:i32 soc_permille:u16 flags:u8` | 19 |
| 0x02 | odometry | `t_ms:u32 x_mm:i32 y_mm:i32 theta_mrad:i16 v_mm_s:i16 w_mrad_s:i16` | 20 |
| 0x03 | imu | `t_ms:u32 accel_mg:i16[3] gyro_cdps:i16[3] temp_cc:i16` (gyro in 0.01 deg/s, temperature in 0.01 C) | 20 |
| 0x04 | key_value | `count:u8` then `count` x (`key_len:u8 key[key_len] tag:u8 value`) | 3 + entries |
| 0x10 | command | `opcode:u8 arg:i32` | 7 |

Battery fields follow the `$BM1` line of the ina219-battery-monitor project:
current positive = discharge, flag bit 0 = INA219 overflow. This project adds
flag bit 7 = "no current sensor" and `soc_permille = 65535` = unknown, which
is what the demo node sends from a plain ADC divider.

Key/value: keys are 1..15 printable ASCII bytes (0x21..0x7E); at most 15
entries; tags 0 = int32, 1 = float32, 2 = bool (one byte, 0 or 1),
3 = string (`len:u8` 0..32, then bytes). A key/value message must be consumed
exactly: trailing bytes make it invalid.

Commands (gateway to node, reliable channel):

| Opcode | Name | Argument |
|---|---|---|
| 1 | set_telemetry_period_ms | 20..60000 |
| 2 | set_pa_level | 0..3 (-18, -12, -6, 0 dBm) |
| 3 | request_status | ignored; the node sends a key/value status next |
| 4 | identify | blink the node LED for `arg` ms (ESP32 build only; on Nano and NUCLEO the LED is on the SCK pin) |

Decoders require the exact length for fixed-size types and the right
version; anything else is rejected.

## 3. Gateway USB serial packets

```
wire   = COBS(packet) 0x00
packet = version:u8 (= 1) kind:u8 seq:u8 length:u8 body[length] crc:u16
crc    = CRC-16/CCITT-FALSE over version .. body
```

This is the same packet layout as the encoder-odometry-firmware protocol, so
a serial-scope style decoder needs only a new kind table (and the
odometry-specific 72-byte frame limit raised: gateway packets can be up to
`6 + LINKCORE_SERIAL_MAX_BODY` bytes, 206 by default and 78 on the Nano).
`seq` counts packets per direction so a reader can detect dropped packets.
115200 baud, 8N1.

| Kind | Direction | Name | Body |
|---|---|---|---|
| 0x01 | gateway to host | message | `channel:u8` (0 reliable, 1 best effort) `pipe:u8 flags:u8` (bit 0 = RPD) then the application message |
| 0x02 | gateway to host | link_stats | 13 x u32: uptime_ms, frames_received, malformed, crc_errors, duplicates, delivered_reliable, delivered_unreliable, unreliable_lost, reliable_sent, reliable_acked, reliable_failed, reliable_retries, resyncs; then u8 hop_index, hop_locked, channel, rpd_percent (56 bytes), once a second |
| 0x03 | gateway to host | command_result | `link_seq:u8 delivered:u8` |
| 0x04 | gateway to host | log | ASCII text |
| 0x81 | host to gateway | send_command | an application message, sent to the node on the reliable channel |
| 0x82 | host to gateway | request_stats | empty |

Worked example (from the vectors): a command `set_telemetry_period_ms 100`
reported as a received message on pipe 1 with RPD set, serial `seq` 0:

```
message body  01 01 01 | 01 10 01 64 00 00 00
packet        01 01 00 0a 01 01 01 01 10 01 64 00 00 00 77 cd
wire          03 01 01 09 0a 01 01 01 01 10 01 64 01 01 03 77 cd 00
```

`nrflink decode capture.bin` and `nrflink monitor --port ...` print these
packets one per line.

## Versioning

Changing the layout or meaning of any existing field needs a new version
byte at the layer concerned (message `version`, serial `version`) or, for
the link frame, a new frame type. All four places must change together:
`lib/linkcore`, `host/src/nrflink`, this document and the shared vectors.
